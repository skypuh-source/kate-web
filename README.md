# kate-web

[![privacy](https://github.com/skypuh-source/kate-web/actions/workflows/privacy.yml/badge.svg)](https://github.com/skypuh-source/kate-web/actions/workflows/privacy.yml)
[![release](https://github.com/skypuh-source/kate-web/actions/workflows/release.yml/badge.svg)](https://github.com/skypuh-source/kate-web/actions/workflows/release.yml)

Неофициальная сборка **Kate Mobile 133.11** с нативным интерфейсом и клиентским
web-каналом VK. Приложение не переписано с нуля: к оригинальному APK применяются
точечные патчи, которые меняют транспорт данных, авторизацию, обновления и часть
поведения интерфейса.

[Скачать последний релиз](https://github.com/skypuh-source/kate-web/releases/latest) ·
[Все релизы](https://github.com/skypuh-source/kate-web/releases)

## Зачем это нужно

Оригинальный Kate работает через официальный `api.vk.com` и быстро упирается во
флуд-лимиты VK (`error 9`), а старый сервер обновлений `katemobile.ru` больше не
поддерживается. `kate-web` сохраняет привычный UI Kate, но получает данные через
живую браузерную сессию VK в WebView:

- куки сессии → `login.vk.ru` → короткоживущий `web_token`;
- запросы методов → `web.api.vk.ru/method/*`;
- LongPoll → `api.vk.ru` через параметры, которые отдаёт web-канал.

Так приложение меньше зависит от ограничений нативного API и продолжает работать
с аккаунтом, который уже авторизован в WebView.

## Возможности

- Лента, диалоги, история сообщений и LongPoll через web-канал.
- Полная загрузка списка диалогов без ручной прокрутки.
- Ответы и уведомления через `notifications.getRedesign` с конвертацией в родные модели.
- Уведомления о сообщениях при закрытом приложении через foreground-сервис-якорь.
- Отдельный канал для службы-якоря и возможность скрыть его уведомление.
- Медиа из галереи устройства, вложения, голосовые с повторной загрузкой при ошибке.
- Исправленные внешние ссылки и разметка постов.
- Закладки, кэш пользователей и другие небольшие исправления UI.
- Автообновление APK через GitHub Releases.
- Максимальная поддерживаемая частота обновления экрана.
- Оптимизации кэша токена, keep-alive соединений и загрузки картинок.

## Как это работает

```text
VK WebView (cookies)
        │
        ▼
login.vk.ru/?act=web_token
        │  web_token
        ▼
web.api.vk.ru/method/<method>
        │
        ▼
Api.sendRequest → родные модели и UI Kate
```

Ключевая точка изменений — `Api.sendRequest`: в запрос добавляются `access_token` и
`client_id` web-клиента, а хост меняется на `web.api.vk.ru`. Заголовок `Authorization`
убирается, чтобы токен не передавался дважды. Для методов, которых нет на web-канале,
используются тонкие конвертеры в родные классы Kate.

LongPoll запускается через `messages.getLongPollServer` и опрашивает `api.vk.ru` с
параметрами `wait`, `mode` и `version`, совместимыми с web-сессией.

## Структура

| Путь | Назначение |
|---|---|
| `orig/Kate_133_11.apk` | исходный APK, эталон для патчей |
| `patches/` | smali-файлы и shell-патчи, применяются по порядку |
| `scripts/decode.sh` | декомпиляция оригинала в `decode/` |
| `scripts/apply.sh` | применение всех `patches/f*` |
| `scripts/build.sh` | сборка, подпись и проверка APK |
| `scripts/check_scope.sh` | проверка состава репозитория |
| `scripts/check_privacy.sh` | проверка на личные данные |
| `tools/apktool_2.12.1.jar` | apktool |
| `keys/debug.keystore` | ключ подписи; не пересоздавать |
| `.github/workflows/` | release и privacy CI |
| `assets/mascot/` | ассеты README |
| `README.md` | описание и инструкции |
| `THIRD_PARTY_NOTICES.md` | лицензии сторонних компонентов |

`decode/`, `dist/`, `Kate.apk` и `version.json` создаются локально и не коммитятся.

## Правила репозитория

В GitHub попадает только то, что непосредственно нужно для сборки, релиза, защиты
репозитория или README. Всё остальное остаётся локально.

Разрешены:

- `orig/`, `patches/`, `tools/`, `keys/` — входные данные и инструменты сборки;
- `scripts/decode.sh`, `apply.sh`, `build.sh` — сборка;
- `scripts/check_privacy.sh`, `check_scope.sh` и два workflow — защита и релиз;
- `README.md`, `THIRD_PARTY_NOTICES.md` и `assets/mascot/` — описание и его ассеты.

Не коммитятся: планы, журналы, аудиты, исследования, эксперименты, отдельные
подпроекты, APK и другие артефакты сборки, логи, временные файлы и скриншоты вне README.

Проверка выполняется в CI через `scripts/check_scope.sh`. Новый путь вне allowlist
блокируется; если файл действительно нужен проекту, его добавляют в allowlist осознанно.

## Сборка

Требования: JDK 17+ и `jarsigner` (входит в JDK). apktool уже лежит в `tools/`.

```sh
sh scripts/decode.sh
sh scripts/apply.sh
sh scripts/build.sh
```

Результат: `dist/kate_web-YYYY-MM-DD.apk`.

`build.sh` создаёт `dist/`, собирает APK, подписывает его `keys/debug.keystore`,
проверяет подпись и печатает MD5.

**Не пересоздавайте `keys/debug.keystore`.** Android не установит обновление поверх
приложения с другой подписью. Смена ключа означает удаление приложения и повторный вход
в аккаунт.

## Релизы и обновления

Релиз запускается тегом:

```sh
git tag v133.xx
git push origin v133.xx
```

GitHub Actions собирает APK, выставляет `versionName` из тега и `versionCode` по формуле
`1000 + номер запуска`, после чего публикует в Release файлы `Kate.apk` и `version.json`.

Штатный `UpdateChecker` приложения читает `version.json` из последнего релиза и
предлагает установить новую версию. Первый переход на сборку с GitHub-обновлениями
может потребоваться выполнить вручную.

## Ограничения

- Нужна живая сессия VK в WebView. Очистка данных приложения стирает куки и требует
  повторного входа.
- Подпись APK должна оставаться неизменной, иначе обновление не установится.
- `targetSdk` удерживается на 29 из-за особенностей `resources.arsc` при сборке apktool;
  на Android 13 это включает legacy-модель доступа к медиа.
- Уведомления при закрытом приложении держатся на foreground-сервисе. Он может
  расходовать батарею и показывать постоянное уведомление; его можно скрыть в настройках.
- VK может изменить web-методы или их ответы в любой момент. Проект не даёт гарантии
  совместимости с будущими версиями VK.
- Это не официальный клиент и не сборка из Google Play.

## Безопасность

- В репозитории нет токенов, куки и пользовательских данных.
- `decode/`, `dist/`, `Kate.apk`, `version.json` исключены из Git.
- `scripts/check_privacy.sh` и workflow `privacy` проверяют коммиты на личные данные.
- `keys/debug.keystore` — тестовая debug-подпись. Не используйте её для сборок,
  которым нужна защищённая production-подпись.
- Не прикладывайте к issue/PR логи с токенами, куки, `remixsid` и персональными данными.

## Разработка

Патчи лежат в `patches/` и применяются в лексикографическом порядке:

- `f*.sh` — выполняют точечные правки декомпилированного дерева;
- `f*.smali` и каталоги с `.smali` — копируются в `decode/`.

После изменения патчей нужно прогнать полный цикл `decode → apply → build` и проверить,
что APK собирается и подписывается. Новые патчи добавляйте с префиксом `f` и следующим
свободным номером.
